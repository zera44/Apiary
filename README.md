# Моя пасіка (Flutter / Dart)

Застосунок для плану пасіки: вулики й перешкоди на нескінченній карті,
шаблони (заготовки) конфігурацій, власні параметри з історією значень і
експортом в Excel. Працює повністю офлайн: усе одразу пишеться в локальну
SQLite. Синхронізація із сервером (Supabase) готується - поки вона вимкнена
(див. «Сервер»).

Це повний переклад Python/Kivy-версії на Flutter. Поведінка екранів та
сама, схема бази даних сумісна зі старою.

## Розробка

Застосунок лише для Android (версії для Windows більше немає).

1. Встанови **Flutter SDK**: https://docs.flutter.dev/get-started/install
   і Android Studio (Android SDK); перевір, чого бракує: `flutter doctor`.
2. У теці проєкту **один раз** згенеруй платформні файли:

   ```
   flutter create --platforms=android --org org.apiary --project-name apiary .
   dart run tool/patch_platforms.dart
   ```

3. Запуск на телефоні чи емуляторі Android:

   ```
   flutter pub get
   flutter run
   ```

   Під час роботи: `r` — миттєво підхопити зміни в коді (hot reload),
   `R` — перезапуск.

Масштаб карти — двома пальцями.

## На телефоні

- **Через кабель:** увімкни на телефоні "Налагодження USB", підключи й
  виконай `flutter run` — застосунок встановиться і запуститься.
- **Готовий APK:** `flutter build apk --release`, файл буде в
  `build/app/outputs/flutter-apk/app-release.apk`.
- **Без встановлення нічого (GitHub Actions):** залий проєкт у репозиторій
  на GitHub. Workflow `.github/workflows/build.yml` сам перевіряє код,
  проганяє тести і збирає **APK для Android** (ручний запуск з гілки —
  пре-реліз `test-<гілка>`, push у main — реліз `latest`).

## Тести

```
flutter test
```

Покривають логіку бази (базові характеристики, undo, групи, поворот,
параметри, історія, черга синхронізації), злиття клітинок, формат шаблонів,
експорт Excel і побудову кожного екрана.

## Типові шаблони

Після встановлення вже є шаблони «Вулик» (1×1) і «Лежак» (2×1), тож перший
вулик ставиться на карту без малювання шаблону. Вони додаються один раз
(позначка в таблиці `app_meta`); видалені користувачем не повертаються.
У пісочниці навчання їх немає — урок вчить створювати шаблон.

## Нагадування про обхід

Для вулика задайте «Періодичність обходу» (днів) і «Дату останнього обходу».
Через стільки днів після цієї дати о 9:00 прийде сповіщення «Ти давно не
заглядав у вулик N. Перевір його», далі — щоперіоду, доки не буде обходу.
Обхід = «Оглянути» → «Зберегти» на вулику: дата останнього обходу
ставиться на сьогодні автоматично (можна змінити вручну в тій самій формі).
Якщо дату не задано, відлік іде від моменту, коли задали періодичність.
Натискання на нагадування відкриває цей вулик на карті одразу з формою
«Оглянути» (так само — після сканування QR-коду вулика).
Сповіщення планує система (працює й при закритому застосунку).

## Назва та іконка застосунку

Назва на телефоні — **Vulyk** (`appName` у
`tool/patch_platforms.dart`). Іконка — пасічник із рамкою
(`design/app_icon/app_icon.pdf`). Щоб її змінити, заміни PDF і виконай
`python3 tool/make_app_icon.py` (потрібні poppler-utils і Pillow): скрипт
оновить `tool/app_icon/`, а `dart run tool/patch_platforms.dart` скопіює
файли в платформну теку Android (звичайна й адаптивна іконка та біла
іконка сповіщень).

## Іконки

Усі іконки — SVG-файли в [`assets/icons/`](assets/icons/README.md), поділені на
`objects/`, `obstacles/` та `ui/`, з реєстром `icons.json`. Їх можна змінювати й
додавати без правок коду — інструкція та правила малювання в
[assets/icons/README.md](assets/icons/README.md). Галерея: `python3 tool/icon_gallery.py`.

## Безпека збірки

* APK підписується ключем із секретів репозиторію `APIARY_KEYSTORE_B64`
  (PKCS12 у base64, псевдонім `apiary`) і `APIARY_KEYSTORE_PASSWORD`. Поки
  їх немає — тимчасовим ключем із `tool/debug.keystore`. CI перевіряє
  сертифікат кожного APK за `tool/signing-cert.sha256` і не публікує збірку
  з іншим підписом.
* Версії залежностей зафіксовано в `pubspec.lock` (`--enforce-lockfile`),
  дії GitHub — за SHA, Flutter — 3.47.5. Токен CI лише на читання (запис
  має тільки публікація релізу). До релізу додаються `SHA256SUMS.txt`.
* Синхронізація працює лише з `https://` адресою сервера (`SUPABASE_URL`).
* Дані застосунку не потрапляють у хмарні резервні копії Android.

## Що виправлено порівняно з Python-версією

1. **"Крок назад" після видалення** більше не ламається через ~20 с:
   відновлення тепер завжди повертає рядок, а видалене остаточно
   прибирається з бази лише через 7 днів після синхронізації.
2. **Перейменування базової характеристики** ("Періодичність обходу" тощо)
   більше не створює дубль при наступному запуску — вони мають сталий
   внутрішній ключ.
3. **Синхронізація** тепер охоплює всі дані: каталог параметрів,
   прив'язки й історію значень (раніше — лише карту й шаблони).
4. Прив'язки параметрів до остаточно видалених об'єктів прибираються
   (історія значень лишається — її видно в каталозі як "Видалений об'єкт").
5. Перевірка інтернету більше не залишає відкриті з'єднання.
6. Синхронізація не губить зміну, зроблену саме в момент відправки.

Нове: масштаб щипком; у редакторі шаблону є кнопка
"назад" з попередженням про незбережені зміни; експорт Excel відкриває
системний діалог "Зберегти як…" (на Android — без дозволів на сховище).

## Сервер (синхронізація, Supabase)

Сервер - [Supabase](https://supabase.com). Адреса й публічний ключ проєкту
задаються під час збірки:

```
flutter run --dart-define=SUPABASE_URL=https://xxxx.supabase.co --dart-define=SUPABASE_ANON_KEY=eyJ...
```

Проєктів два: тестовий (збірки гілок) і робочий (реліз з `main`). У GitHub
(Settings → Secrets and variables → Actions) - секрети
`SUPABASE_URL_TEST`, `SUPABASE_ANON_KEY_TEST`, `SUPABASE_URL_PROD`,
`SUPABASE_ANON_KEY_PROD`; збірка APK сама бере потрібну пару. Як створити й
налаштувати проєкти (таблиці, правила доступу, сховище, нічні копії,
keep-alive) - [`supabase/README.md`](supabase/README.md).

Поки адреси й ключа немає, синхронізація **вимкнена** і нічого не робить
із даними: зміни лишаються в черзі (`synced = 0`), позначки «видалено» не
стираються - сервер отримає все, коли синхронізацію буде налаштовано.
Усе локальне (дані, фото, резервні копії, налаштування) працює повністю.
Див. `lib/services/app_config.dart`, `lib/data/sync_service.dart`.

Що ще не налаштовано й до чого треба повернутися - `docs/REMINDERS.md`.

## Резервні копії на телефоні

Кожні 6 годин (фоном через WorkManager і при відкритті застосунку, якщо
минуло більше 6 год) база копіюється в теку `backups/` поряд із нею:
узгоджений знімок `VACUUM INTO` (на Android 7-10, де його немає, - копія
файлу всередині транзакції), потім `PRAGMA integrity_check`; пошкоджена
копія не зберігається. Тримаються копії за 2 дні (~8 шт.), найновіша -
завжди. Фото в копію не входять: вони лишаються в теці фото, і поки на них
посилається копія, не прибираються.

Налаштування → «Головне» → «Резервні копії»: список, «Відновити» (перед ним
поточний стан зберігається окремою копією - відновлення можна скасувати),
«Зберегти у файл» / «Поділитися». Відновлення переносить дані у відкриту
базу в одній транзакції; записи, яких у копії не було, стають позначками
«видалено» (щоб сервер не повернув їх з іншого телефона), а все відновлене
стає в чергу на відправку. Див. `lib/services/backups.dart`.

## Тексти інтерфейсу (кілька мов)

Нові тексти - лише через `tr` (`lib/l10n/`): `tr.settingsTabMain` тощо.
Мова - клас, що реалізує `AppStrings` (поки `AppStringsUk`); компілятор не
пропустить мову, де бракує тексту. Старі тексти переносяться поступово.

## Версія бази й міграції

Версія схеми - `AppDatabase.schemaVersion` (зберігається в базі як
`PRAGMA user_version`). Нова версія - новий крок у `AppDatabase.migrations`:
він виконується рівно раз, в одній транзакції, і не повинен губити дані
(тест - `test/database_migration_test.dart`). Базу новішої версії стара
версія застосунку не відкриває (зрозуміла помилка замість зіпсованих даних).

## Вхід через Google

Перший екран — вхід через Google, він обов'язковий. Після першого входу
користувач запам'ятовується на пристрої (файл `account.json` у теці даних
застосунку), тож далі застосунок відкривається одразу на головному екрані
й працює без інтернету. «Вийти» — внизу головного екрана.

Вхід іде через пакет `google_sign_in` — див. `lib/services/auth.dart`.

Налаштування (один раз, у [Google Cloud Console](https://console.cloud.google.com)):

1. Створи проєкт → «APIs & Services» → «OAuth consent screen»: тип External,
   назва Vulyk, пошта підтримки; додай свою пошту в «Test users» (поки
   застосунок не опубліковано, увійти зможуть лише тестові користувачі).
2. «Credentials» → «Create credentials» → «OAuth client ID»:
   * **Android**: package name `org.apiary.apiary`, SHA-1 ключа підпису
     (тимчасовий ключ із `tool/debug.keystore`:
     `0D:E8:20:13:CC:D7:E3:22:EF:FE:AE:A4:BD:90:6B:D8:52:AB:2B:B7`; коли
     з'явиться справжній ключ — додай окремий клієнт і з його SHA-1);
   * **Web application** — його Client ID потрібен Android-входу як
     `serverClientId`.
3. У репозиторії GitHub → Settings → Secrets and variables → Actions:
   `APIARY_GOOGLE_SERVER_CLIENT_ID` (Web client ID).

Локально: `flutter run --dart-define=APIARY_GOOGLE_SERVER_CLIENT_ID=…`.
Без цих значень екран входу пише «Вхід через Google не налаштовано в цій збірці».

## Зворотний зв'язок

У бічному меню карти (три смужки) є пункт «Зворотний зв'язок»: користувач
пише текст, і той приходить листом на **myapiaryrezvin@gmail.com**. Пароль від
пошти в застосунку не зберігається — лист пересилає сервіс форм
[Formspree](https://formspree.io) (безкоштовно — до 50 листів на місяць).

Налаштування (один раз):

1. Зареєструйся на formspree.io з адресою myapiaryrezvin@gmail.com і
   підтверди її з листа.
2. Створи форму (New Form), листи — на myapiaryrezvin@gmail.com. Скопіюй її
   адресу виду `https://formspree.io/f/xxxxxxxx`.
3. У репозиторії GitHub: Settings → Secrets and variables → Actions →
   New repository secret, ім'я `APIARY_FEEDBACK_URL`, значення — ця адреса.

Наступні збірки CI вже надсилатимуть відгуки. Локально:
`flutter run --dart-define=APIARY_FEEDBACK_URL=https://formspree.io/f/xxxxxxxx`.
Без адреси (або без інтернету) застосунок каже, що не вдалося надіслати, і
пропонує скопіювати текст разом з адресою пошти.

## Стара база з Python-версії

Схема та сама (нові колонки додаються автоматично), тож файл `apiary.db`
зі старої версії можна просто підкласти в теку даних застосунку.
Автоматичного імпорту на телефоні поки немає — це можна додати окремою
кнопкою.

## «Що нового» — автоматично з комітів

Екран «Що нового» і опис релізу на GitHub збираються з історії git
(`tool/whats_new.py`, запускається в CI перед збіркою). У опис коміту,
що змінює щось помітне для пасічника, додайте рядки:

```
Нове: Коротко, що з'явилось (мовою пасічника)
Нове(5): Те саме з вагою 1..5 — що більша, то вище в переліку
Виправлено: Яку помилку виправлено
```

Одразу на екрані — 20% найважливіших змін, решта й виправлення — у «Ще».
Коміти без цих рядків (тести, CI, рефакторинг) у «Що нового» не потрапляють.
