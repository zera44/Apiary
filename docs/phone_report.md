## Проблеми детально

### 1. Критична — синхронізація зламана: SUPABASE_URL збірки вказує на github.com
- **Екран:** Налаштування → Акаунт → Синхронізація; Мої пасіки → Помічники.
- **Кроки:** увійти через Google → запустити застосунок → відкрити Налаштування → Акаунт.
- **Очікувалось:** тихий вхід на сервер, «Синхронізувати зараз» працює, можна створити посилання-запрошення.
- **Сталося:** кожен запуск вхід на сервер відхиляється з HTML-сторінкою (типова сторінка помилки GitHub із CSP `default-src 'none'`). В офлайні видно саме ім'я хоста:
  ```
  12:21:49.501 I flutter : Сервер: сервер відхилив (422): <!DOCTYPE html>
  12:22:46.869 I flutter : Сервер: немає зв'язку із сервером (Failed host lookup: 'github.com')
  ```
  Повторюється на кожному холодному старті (11:39:59, 12:21:49, 12:27:47, 12:27:53, 12:28:00).
  Через це «Синхронізувати зараз», «Завантажити з сервера» та «Створити посилання-запрошення» неактивні.
- **Скріншоти:** `57_account.jpg`, `64_helpers.jpg`.
- **Порада:** у GitHub → Settings → Secrets перевірити `SUPABASE_URL_TEST` (і `SUPABASE_URL_PROD`): там має бути `https://<ref>.supabase.co`, а не посилання на GitHub. У `build.yml` додати перевірку на кшталт `[[ "$SUPABASE_URL" == https://*.supabase.co ]] || exit 1`, а в `AppConfig.syncConfigured` — вважати адреси не з `supabase.co` (або без `/auth/v1`) неналаштованими.

### 2. Висока — «Увійдіть через Google», хоча вхід уже є
- **Екран:** Налаштування → Акаунт; Помічники.
- **Кроки:** увійти через Google (картка «Акаунт» показує ім'я, пошту, «Вхід через Google») → подивитися картку «Синхронізація».
- **Очікувалось:** пояснення, що не вдалося підключитися до сервера, і кнопка «Підключитися».
- **Сталося:** текст `syncNeedsSignIn` «Увійдіть через Google, щоб синхронізувати дані між телефонами»; кнопки тьмяні, тап нічого не робить і нічого не каже. На «Помічниках»: «Запросити помічника можна, коли … ви увійшли через Google».
- **Скріншоти:** `57_account.jpg`, `58_sync_tap.jpg`, `64_helpers.jpg`.
- **Порада:** коміт 838011c (`lib/ui/sync_status.dart:13` → `serverNotConnected`) це частково закриває — потрібна нова збірка й повторна перевірка. На «Помічниках» теж розрізнити «немає входу Google» і «немає зв'язку із сервером».

### 3. Висока — `database_closed` після завершення уроку
- **Екран:** Навчання → «Базові поняття» → … → «Завершити».
- **Кроки:** пройти урок до кроку з панеллю вулика → натиснути «Завершити».
- **Очікувалось:** тихе повернення на головний.
- **Сталося:** повернення відбулося, але в журналі:
  ```
  12:12:29.781 17166 E flutter : [ERROR:flutter/runtime/dart_vm_initializer.cc(40)] Unhandled Exception: DatabaseException(error database_closed)
  ```
  Ймовірно, частину запису прогресу або даних уроку втрачено.
- **Порада:** у `lib/screens/tutorial_screen.dart:116` і `:231` `sandbox?.db.close()` викликається одразу після `nav.push(...)`/`popUntil`, поки `MapScreen(repo: sb)` ще закривається й дописує в пісочницю (dispose, `lesson.onSave`, таймери). Закривати базу після кадру (`await WidgetsBinding.instance.endOfFrame`) або після того, як усі звернення до `sb` завершаться. Ще варіант: у репозиторії пісочниці ігнорувати запити після `close()`.

## Що працює добре
- **Огляд вулика:** вибір дати, мітки матки, кількості вуличок, нотатки. Після збереження значення одразу в панелі й в історії (`09_after_save.jpg`, `38_history_param.jpg`). Поле «Підгодівля зі складу» з'являється, коли на складі є товар.
- **Нотатки:** додавання, мітка «Огляд» для нотаток з огляду, фільтри.
- **Режим редагування:** додати вулик (1×1), меню «Властивості / Повернути / Видалити».
- **Склад:** номенклатура, прихід із ціною (25 грн/кг рахується), списання, **валідація** «Можна списати не більше 10 кг», історія руху (`25_stock_out_over.jpg`, `26_stock_history.jpg`).
- **Фінанси:** витрата й дохід, діаграма, баланс, «Усі операції». Прихід на склад автоматично йде у витрати «Внесено на складі». Порожній рядок товару з «Покласти на склад» не створює безіменної номенклатури.
- **Історія:** за параметрами й складом, експорт в Excel доступний.
- **QR:** генерація наліпок для 2 вуликів, нумерація, друк і PDF (`42_qr_result.jpg`).
- **Розмір шрифту:** 4 рівні застосовуються одразу всюди; діалог огляду при «Дуже великому» перебудовується акуратно (`48_xl_inspect.jpg`).
- **Резервні копії:** ручна копія створюється миттєво (240 КБ), список з «Відновити» і «Зберегти у файл».
- **Урок «Базові поняття»:** кроки йдуть по черзі, працює в пісочниці, реальні дані не змінюються (`75_map_after_lesson.jpg`).
- **Стійкість:** monkey 3000 подій (throttle 150 мс) — **0 падінь, 0 ANR**. Поворот екрана й згортання / повернення (×3, а також 20 с у фоні) зберігають відкриту панель. `FATAL EXCEPTION` і ANR у журналі немає.
- Незбережені форми («Нова витрата») питають «Вийти без збереження?».

## Журнал (logcat) — вибірка
- `FATAL EXCEPTION`: **0**. ANR: **0**.
- `E/flutter`: 1 необроблений виняток (`database_closed`, див. № 3) + 1 службове «Reported frame time is older than the last one; clamping» (12:22:28, нешкідливе).
- SQLite: помилок застосунку немає (рядки `TransportRuntime.SQLiteEventStore` — службова телеметрія ML Kit під час відкриття QR-сканера).
- Supabase / HTTP: див. № 1 — `422` з HTML і `Failed host lookup: 'github.com'` на кожному старті.
- Решта E-рядків — шум прошивки Realme (`IJankManager`, `OplusPredictiveBackController`, `perfctl`) і закриття камери сканера (`BufferQueue has been abandoned`).

## Побічні зміни на телефоні після тесту
Видаляти нічого не довелося, тестові дані лишилися:
- вулик «Вулик 2» на «Пасіці 1», огляд «Вулик 1» (15.10, жовта мітка, 7 вуличок), нотатки «QA test note», «QA note 2»;
- склад «QA sugar» (7 кг), фінанси: прихід 250 ₴, витрата «Ліки» 120 ₴, дохід «Продаж меду» 900 ₴;
- QR-коди №0001 і №0002 прив'язані до вуликів, ручна резервна копія 12:07;
- від monkey: «Пасіка 2» та інші випадкові зміни. Резервна копія 12:07 зроблена **до** monkey — з неї можна відновитися.

Розмір шрифту повернуто на «Звичайний» до monkey (monkey міг його змінити), поворот екрана й мережу відновлено.
